# 本地配方批次与放行

这是一个在本机运行的本地配方批次与放行台账。数据保存在调用方指定的本地目录中，
不同目录互相独立；程序退出后重新打开同一位置，已登记的数据及请求结果仍完整可查。

## 使用

```bash
go test ./...
```

### 打开台账

```go
s, err := release.Open("/path/to/data") // 目录不存在会自动创建；空目录得到空台账
defer s.Close()
```

已有台账文件但无法读取或解析时，`Open` 返回 `release.ErrCorruptData`，
不会当成空台账继续保存。零字节的台账文件同样按损坏处理（与“没有台账文件”
区分开）：无论文件原本就为空还是使用过程中被清空，都会返回 `ErrCorruptData`，
原文件保持零字节，不会补写成空台账，也不会凭此前的记录自动还原。每个批次绑定的配方编号与版本号必须共同指向一个
已登记的配方版本；任一批次缺少对应版本（同编号的其他版本不算），`Open`
同样返回 `ErrCorruptData`，错误信息包含该批次编号及其所需的配方编号、版本号。
同一台账内一个批次编号只能对应一条批次记录：只要出现两条同编号批次
（即使绑定不同配方版本、计划份数或状态不同，甚至两条内容完全一致），
`Open` 同样返回 `ErrCorruptData`，错误信息包含重复的批次编号；不会挑选
第一条或最后一条，也不会合并投料、自动改号或删除一条后继续，其他批次
完整或投料数量吻合都不能放行（不同编号的批次共用同一配方版本是合法的）。
台账打开后文件内容若被改坏，下一次查询或写入在重新读取时也会返回
`ErrCorruptData`，被拒绝的读取不会删除批次或补造配方，被拒绝的写入不留下
任何业务记录、不占用请求编号；恢复缺失的原配方版本后重新打开即可继续使用。

### 登记配方版本

配方由配方编号与版本号共同识别，每个版本包含名称和至少一种物料，
物料记录编号和生产一份所需的克数（正数、最多三位小数）。

```go
recipe, err := s.RegisterRecipe("req-001", "R1", "v1", "配方一", []release.MaterialInput{
    {MaterialNo: "M1", Grams: "100"},
    {MaterialNo: "M2", Grams: "0.5"},
})
```

同一版本内物料编号不可重复；已登记的版本内容不可覆盖（`ErrRecipeExists`）。

### 批次状态机

```go
batch, err := s.CreateBatch("req-002", "B1", "R1", "v1", 10) // 草稿，份数为正整数
batch, err = s.UpdateDraftBatch("req-003", "B1", "", "", 20) // 草稿可改份数/配方
batch, err = s.StartBatch("req-004", "B1")                    // 草稿 → 执行中
batch, err = s.CloseBatch("req-005", "B1")                   // 执行中 → 已关闭
```

开始执行后计划份数与配方版本固定；只有执行中的批次可以关闭，
关闭表示确认已有投料，不要求数量吻合；关闭后不能追加投料或重新打开。

### 投料

执行中可以分多次追加投料，物料必须属于该批次绑定的配方版本：

```go
feeding, err := s.AddFeeding("req-006", "B1", "M1", "100.5", time.Now(), "张三")
```

投料按成功登记的先后顺序编号，不按投料时间重排；已登记的投料不能修改或删除。

### 查询

```go
batch, err := s.GetBatch("B1") // 不存在时返回 release.ErrNotFound
recipe, err := s.GetRecipe("R1", "v1")
```

批次查询返回所用配方版本、计划份数、状态和全部投料，
并按物料逐项列出应投量（每份克数 × 计划份数）、累计实投量和实投减应投的差额；
没有投料的物料也会显示，超投不会抵消其他物料的欠投。
返回的视图是台账数据的副本，调用方修改不会影响台账。

### 请求编号与幂等

每次写入都带请求编号（第一个参数）。同一位置内：

- 相同编号 + 相同操作内容重复提交，返回第一次成功的结果，不新增批次或重复投料
  （即使批次已经关闭）；
- 相同编号用于其他操作或不同内容，返回 `release.ErrRequestConflict`；
- 失败不占用编号，也不留下部分记录或状态变化。

并发提交通过进程内互斥与文件锁（flock）串行化，同一请求同时到达只产生一次业务变更。

## 数量精度

克数以千分之一克为单位定点存储与计算（`100`、`100.5`、`0.001` 合法；
`0`、`-1`、`1.2345` 非法），份数为正整数，避免浮点误差。

同一批次内，每种物料的累计实投量上限为 9223372036854775.807 克
（按物料分别判断，其他物料的投料量不参与）；追加后恰好等于上限仍可成功，
超过则 `AddFeeding` 返回 `ErrInvalidInput`，不保存本次投料，
失败不占用请求编号。
