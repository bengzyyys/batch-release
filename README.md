# 本地配方批次与放行

这是一个在本机运行的本地配方批次与放行台账。数据保存在调用方指定的本地目录中，
不同目录互相独立；程序退出后重新打开同一位置，已登记的数据及请求结果仍完整可查。

## 使用

```bash
go test ./...
```

### 打开台账

```go
s, err := release.Open("/path/to/data") // 目录不存在会自动创建；空目录得到空台账
defer s.Close()
```

已有台账文件但无法读取或解析时，`Open` 返回 `release.ErrCorruptData`，
不会当成空台账继续保存。零字节的台账文件同样按损坏处理（与“没有台账文件”
区分开）：无论文件原本就为空还是使用过程中被清空，都会返回 `ErrCorruptData`，
原文件保持零字节，不会补写成空台账，也不会凭此前的记录自动还原。每个批次绑定的配方编号与版本号必须共同指向一个
已登记的配方版本；任一批次缺少对应版本（同编号的其他版本不算），`Open`
同样返回 `ErrCorruptData`，错误信息包含该批次编号及其所需的配方编号、版本号。
读取每个已保存批次时，其状态必须精确对应 `draft`、`executing`、`closed`
三个值之一：状态缺失、为空、为 `null`，或保存成 `ready` 等其他字符串都不合法；
大小写不同（如 `Draft`）以及前后多了空格（如 ` draft `）也不会自动当成某个
合法状态。任一批次状态无法识别，`Open` 即返回 `ErrCorruptData`，错误信息
包含问题批次编号及实际读到的状态，状态为空或缺失时会明确说明为空或缺失；
不会根据有没有投料替它猜状态，不会补成草稿，也不会删除或跳过该批次继续返回
其他批次与配方——即使配方版本、计划份数正常，且尚未投料或投料数量已经吻合。
读取每个已保存配方版本时，它必须至少包含一种物料，与登记配方时的规则一致：
物料列表保存成空数组、`null` 或字段缺失，即使名称、编号、版本号齐全且台账
内容能正常解析，`Open` 也返回 `ErrCorruptData`，错误信息包含问题配方的编号
与版本号并明确说明它没有物料。这项检查覆盖所有已保存版本，不只当前批次使用
的版本：尚未被任何批次引用的空物料版本同样拒绝；同一配方编号下另有完整版本
不能代替问题版本作为读取依据；台账中存在其他正常配方与批次，或调用方只查询
正常记录，都不能绕过。采用空物料版本的批次即使份数为正、状态合法、尚未投料，
也不能以“没有数量差额”为由继续返回结果。这与没有登记任何配方的空台账不同：
空台账没有配方记录，仍可正常使用。拒绝读取不会补造物料、不会删除问题版本，
原文件保持原样。读取每个已保存批次时，其计划份数必须为正整数；按该批次实际绑定的配方版本
计算，每种物料的应投量（每份克数 × 计划份数）都必须能精确表示到千分之一克，
且不能超过 9223372036854775.807 克。任一批次份数为零或负数，或某物料应投量
超限，`Open` 同样返回 `ErrCorruptData`，错误信息包含批次编号与计划份数，
超限时还包含对应物料及绑定的配方编号、版本号。上限按每种物料分别判断，
多种物料的应投量相加超过上限不算非法，单种物料恰好等于上限仍可读取。
这项检查针对整份台账、覆盖草稿/执行中/已关闭全部状态，与本次查询哪个批次
无关。读取每个已保存批次的投料列表时，登记序号还必须与记录在列表中的位置
一致：第一条序号为 1，此后每条依次加 1。零、负数、漏号、重号、跳号，或
只调换记录位置却未同步序号（例如三条记录序号为 1、1、3 或 1、3、2），
即使物料归属与数量全部合法，`Open` 也返回 `ErrCorruptData`，错误信息包含
问题批次编号、该记录在列表中的位置、实际序号与应有序号；系统不会自行重排、
补号或删除投料。不同物料的投料共用所在批次的这一序列，不按物料另起编号；
不同批次各自从 1 开始。空投料列表不构成序号错误。投料时间只由调用方填写、
从不参与排序，时间相同或后一条早于前一条都不影响序号合法性。台账打开后文件
内容若被改坏，下一次查询或写入在重新读取时也会返回
`ErrCorruptData`，被拒绝的读取不会删除批次或补造配方，被拒绝的写入不留下
任何业务记录、不占用请求编号；恢复缺失的原配方版本、改为合法计划或修正登记
序号后重新打开即可继续使用。

### 登记配方版本

配方由配方编号与版本号共同识别，每个版本包含名称和至少一种物料，
物料记录编号和生产一份所需的克数（正数、最多三位小数）。

```go
recipe, err := s.RegisterRecipe("req-001", "R1", "v1", "配方一", []release.MaterialInput{
    {MaterialNo: "M1", Grams: "100"},
    {MaterialNo: "M2", Grams: "0.5"},
})
```

同一版本内物料编号不可重复；已登记的版本内容不可覆盖（`ErrRecipeExists`）。

### 批次状态机

```go
batch, err := s.CreateBatch("req-002", "B1", "R1", "v1", 10) // 草稿，份数为正整数
batch, err = s.UpdateDraftBatch("req-003", "B1", "", "", 20) // 草稿可改份数/配方
batch, err = s.StartBatch("req-004", "B1")                    // 草稿 → 执行中
batch, err = s.CloseBatch("req-005", "B1")                   // 执行中 → 已关闭
```

开始执行后计划份数与配方版本固定；只有执行中的批次可以关闭，
关闭表示确认已有投料，不要求数量吻合；关闭后不能追加投料或重新打开。

### 投料

执行中可以分多次追加投料，物料必须属于该批次绑定的配方版本：

```go
feeding, err := s.AddFeeding("req-006", "B1", "M1", "100.5", time.Now(), "张三")
```

投料按成功登记的先后顺序编号，不按投料时间重排；同一批次不同物料共用这一
序列、从 1 连续编号，不同批次各自从 1 开始。即使两条投料时间相同，或后一条
填写的时间早于前一条，登记顺序与序号也保持不变。已登记的投料不能修改或删除；
重新读取台账时若发现序号重号、跳号或与记录位置不符，整份台账按损坏处理
（见“打开台账”），不会自行重排或补号。

### 查询

```go
batch, err := s.GetBatch("B1") // 不存在时返回 release.ErrNotFound
recipe, err := s.GetRecipe("R1", "v1")
```

批次查询返回所用配方版本、计划份数、状态和全部投料，
并按物料逐项列出应投量（每份克数 × 计划份数）、累计实投量和实投减应投的差额；
没有投料的物料也会显示，超投不会抵消其他物料的欠投。
返回的视图是台账数据的副本，调用方修改不会影响台账。

### 请求编号与幂等

每次写入都带请求编号（第一个参数）。同一位置内：

- 相同编号 + 相同操作内容重复提交，返回第一次成功的结果，不新增批次或重复投料
  （即使批次已经关闭）；
- 相同编号用于其他操作或不同内容，返回 `release.ErrRequestConflict`；
- 失败不占用编号，也不留下部分记录或状态变化。

并发提交通过进程内互斥与文件锁（flock）串行化，同一请求同时到达只产生一次业务变更。

## 数量精度

克数以千分之一克为单位定点存储与计算（`100`、`100.5`、`0.001` 合法；
`0`、`-1`、`1.2345` 非法），份数为正整数，避免浮点误差。

同一批次内，每种物料的累计实投量上限为 9223372036854775.807 克
（按物料分别判断，其他物料的投料量不参与）；追加后恰好等于上限仍可成功，
超过则 `AddFeeding` 返回 `ErrInvalidInput`，不保存本次投料，
失败不占用请求编号。

每种物料按计划计算的应投量（每份克数 × 计划份数）同样以该值为上限、
按物料分别判断：创建或调整草稿批次导致某物料应投量超限时，该次提交
返回 `ErrInvalidInput` 且整体不落盘；已保存批次的份数或应投量不合法
则属于数据损坏，下一次读取返回 `ErrCorruptData`（见“打开台账”）。
